Both hosts use round-robin routing with `session-affinity: false`. The November 2 affinity trial did not meet its frozen cache or latency benefit criteria. Five paired Mac comparisons completed 120 synthetic Luna requests. Only one pair reduced uncached input with affinity. This supports returning to the original routing policy, but does not establish equivalence for Will, other models, or native T3 traffic. See [the comparison and operating decision](cache-affinity-validation.md).

`fleet-release.json` pins five routing fields separately for `arm64` and `amd64`. Will's `config-policy.json` must agree with the `amd64` tuple. The inactive settings remain `session-affinity-ttl: 1h`, `session-affinity-subagents: false`, and `session-affinity-rebind-on: any`. The verifiers detect changes to these fields even while affinity is disabled. Copy the manifest and verifier helper together when updating deployed ops files.

The earlier canary verified account continuity, independent child distribution, fork inheritance, and hot-reload rollback. Those functional results did not establish cache savings. Affinity binds per provider and model, refreshes its idle TTL on every hit, and can concentrate requests without a session ID when their opening text matches. Any future trial needs evidence that its benefit justifies that concentration. Named Claude prefixes continue to select their intended accounts. Both hosts run `v8.0.27-fleet.3` from source `07e5dff992f2ae93bd49f6a3de0ba158816a2dcc`, deployed sequentially with owner approval on October 15, 2026. It extends the one-minute client retry-header limit to auth-unavailable and Home errors and adds an optional quota cooldown maximum. Both live management APIs report `quota-cooldown-max-seconds: 3600` and `save-cooldown-status: true`. Their legacy configuration files use the root keys. Nested configurations use `routing.cooldown`. A binary upgrade alone leaves the cap disabled.

The cap applies to fresh quota errors, saved records and reloads, including different model deadlines on one account. It makes normal requests eligible to test recovery after at most the configured quota wait; another upstream 429 blocks the account again. It does not poll upstream or guarantee a strict request-per-hour limit under concurrency. Legacy state followed by a non-quota error remains conservative: that model and the model-less account summary may retain the old block, while an unaffected model can recover. The reported reset is retry eligibility, not a promise of an upstream quota reset.
